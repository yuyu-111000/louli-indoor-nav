# 城西银泰1F数据适配

2026-10-10。当前默认场馆 `yintai-demo` 使用小组提供的 `城西银泰3D地图数据/kiosk-map.json` 的1F，不进行跨楼层导航。31个颜色区域的多边形顶点、10条店名、区域归属和clear/review标记均保留；4条店名仍待核对。两个星巴克使用不同POI编号，不合并。

坐标由照片像素转换为图上单位：`x=(px-40)/10`，`y=(py-215)/10`，范围152×88，寻路分辨率0.5。10只用于缩放显示，不是米制比例。原图为1706×1279，静态副本及1F索引位于 `frontend/data/yintai-kiosk/`。“逐层看图”打开独立1F浅立体查看页，可对照原图；主页面四步使用同一个原生Canvas地图。

照片只给出了铺位轮廓和店名相对位置，没有实测店门或通道图。适配器用铺位凸包扩展出的外框作为展示边界，另为照片两处灰色留空区域添加推定障碍。轮廓、障碍之外的留白用于演示寻路。起点“演示起点”在留白中，不能视为已核实入口；各店终点是同一连通区域内、靠近文字位置的演示接近点。`map.rooms` 的小矩形只是旧接口锚点，实际绘制和障碍使用 `map.trace.zones` 多边形。

候位、返回提醒及橙色信标继续模拟。信标按入口参考点、店铺接近点及留白间隔布置，并在可通行格网上取点；无线参数与定位误差为演示参数，没有现场采样。距离显示“图上单位”，时间为模型演示，不可当作实际步行或排队估计。

## 重新生成与迁移

在项目根目录运行：

```sh
python backend/build_yintai_floor.py
```

脚本同时更新后端种子、静态种子、1F查看索引与原始照片副本。原内置仿真包保存在 `examples/yintai-simulated-legacy.json`。首次升级数据库时仅迁移与旧种子匹配的城西银泰包，旧包和当时队列先写入 `seed_backups` 表；其它场馆、用户自定义图与反馈保留。重启不会重复覆盖新包的队列。

## 验证范围

前端测试核对全部31个轮廓顶点、10条店名及可信度，逐一求路线并采样检查不进入阻挡格子。后端测试覆盖轮廓包校验、非法照片路径、无效区域引用、旧包备份迁移、其它数据保留以及再次启动不覆盖队列。浏览器另检查四步共用1F、图上选择同名不同ID的店铺、暂停与重置、信标闪烁、桌面及手机布局。实地比例、门点、入口、可通行拓扑和跨层连接仍需进一步补充。

2026-10-10 楼层选择扩展：路线仿真页可切换 B1 至 4F，采用每层照片轮廓和原始店名。新增楼层从静态包加载，目标位于本层最大连通留白区域；店门和跨层连接仍未测绘。1F 保持原接口队列，其余楼层为本地定位与路线仿真，不向1F队列接口写入。运行适配脚本会保留五层查看数据并生成各层独立包。
